# Google Authorized Buyers 上的安全预定向更改：分阶段、预览、历史和回滚

**原子事实：** 原生 Google Authorized Buyers 预定向 UI 既没有变更历史，也没有回滚。

每个生产运营商最终都会做出一个让胜出率暴跌或浪费激增的变更。没有工具，唯一的恢复方法就是凭记忆或旧 CSV 手动重建之前的状态。

## 最小可行的安全工作流

任何允许你在生产环境中编辑预定向的系统都必须提供：

- **预览 / 试运行** —— 在任何内容发送给 Google 之前，显示将要发送的确切差异。
- **分阶段** —— 在你明确确认“推送到 Google”之前，变更不会生效。
- **审计** —— 谁在何时更改了什么，以及前后值是什么。
- **快照 + 回滚** —— 之前的状态被存储，可以一键恢复。

Cat-Scan 正是围绕这个契约构建的。

## Cat-Scan 中的工作流如何运作

1. 运营商打开一个预定向配置（在首页或设置中）。
2. 编辑一个或多个字段（排除的地理、尺寸、最大 QPS、发布商阻止等）。
3. 点击 **预览**。Cat-Scan 显示将要做的精确变更。
4. 如果满意，点击 **应用**（或“是，推送到 Google”）。
5. 变更被发送到 Authorized Buyers API。
6. 配置状态的快照被存储。
7. 该操作出现在全局历史时间线中（`/history`）。

如果胜出率下降或浪费激增，运营商前往历史，选择该变更，预览回滚，然后确认。之前的状态会被恢复。

**原子事实：** Cat-Scan 中的每个预定向变更都会被记录，包含时间戳、用户身份、旧值、新值，以及用于回滚的完整快照。

## 发布商允许/拒绝列表

在原生 UI 中管理发布商阻止特别痛苦（每次变更都需要完整的 CSV 往返）。

Cat-Scan 为每个配置提供搜索 + 阻止/允许编辑器，支持批量操作和即时预览。这是真实席位最高 ROI 的功能之一。

## 为什么这不仅仅是便利

没有安全工具，运营商会变得保守。他们会让坏流量继续流动，因为“更改配置有风险且难以撤销”。这种保守直接以浪费的 QPS 和机会成本的形式 costing 钱。

预览 + 快照 + 回滚的存在改变了风险计算。运营商可以更快地做出更多变更，并产生可衡量的结果。
