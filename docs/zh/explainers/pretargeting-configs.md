# 预定向配置是大多数 Authorized Buyers 买家的主要控制面

**原子事实：** 每个 Google Authorized Buyers 席位只能获得正好 10 个预定向配置。

其他所有事情（竞价器逻辑、素材选择、频次控制）都发生在流量已经被发送给你之后。预定向是你在交易所侧唯一能控制流量的手段。

## 一个预定向配置实际控制什么

每个配置都是一组规则，告诉 Google：“只向我发送匹配这些条件的竞价请求。”

| 字段                | 效果                                                                 | 常见错误 |
|---------------------|----------------------------------------------------------------------|----------|
| **状态**            | 激活（接收流量）或暂停                                               | 留下死配置处于激活状态 |
| **最大 QPS**        | 该规则集接受的每秒查询上限                                           | “以防万一”设置得过高 |
| **包含的地理**      | 要接收流量的国家、地区或城市（仅粗粒度桶）                           | 只依赖宽泛的“欧洲”或“亚洲” |
| **排除的地理**      | 即使匹配包含规则也要阻止的地理                                       | 没有积极使用排除 |
| **包含的尺寸**      | 接受的特定广告尺寸，或“全部”                                         | 当你只有固定尺寸素材时使用“全部” |
| **格式**            | 创意类型：VIDEO、DISPLAY_IMAGE、DISPLAY_HTML、NATIVE                 | 接受你没有素材的格式 |
| **平台**            | 设备类型：DESKTOP、MOBILE_APP、MOBILE_WEB、CONNECTED_TV              | 将移动应用流量发送给仅支持桌面的活动 |
| **发布商**          | 特定域名或应用包的允许/拒绝列表                                      | 通过 Google 笨拙的 CSV 上传/下载循环管理 |

**原子事实：** Google 仍然只暴露粗粒度的地理桶（美国东部、美国西部、欧洲、亚洲等）。预定向内部不支持细粒度的城市或 DMA 定位。

## 为什么原生 UI 如此痛苦

Authorized Buyers 预定向界面要求下载 CSV 模板、离线编辑，然后重新上传，即使只改一行也是如此。没有历史、没有影响预览，也没有简单的回滚。

这正是 Cat-Scan 旨在解决的问题。

## 安全变更工作流（真实运营商需要什么）

任何允许你在生产环境中编辑预定向的系统都必须支持：

1. 编辑 UI（或通过 API）。
2. 试运行/预览——在任何内容推送到 Google 之前，显示将要发送的确切差异。
3. 分阶段——在你明确确认“推送到 Google”之前，变更不会生效。
4. 审计——谁在何时更改了什么，以及前后值是什么。
5. 快照 + 回滚——之前的状态被存储，可以一键恢复。

Cat-Scan 在 Authorized Buyers API 之上实现了完全这个流程。变更会被预览，然后显式推送，然后创建快照以便立即回滚。

请参阅手册章节中的完整描述以及平台中的实现。

## 10 个配置并不多

只有十个槽位，你很快就会学会无情：

- 一到两个“宽泛但安全”的配置用于经过验证的流量。
- 几个狭窄、高精度的配置用于你有强力素材覆盖的特定地理 + 尺寸 + 格式。
- 暂停的配置用作推广前的分阶段区域。

任何没有积极产生出价或花费的配置都在消耗你宝贵的十个槽位之一，应该被暂停或删除。
