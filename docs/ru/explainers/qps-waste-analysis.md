# Анализ потерь QPS по издателю, гео и размеру в Authorized Buyers

**Атомарный факт:** Google отправляет вам сотни размеров объявлений и тысячи издателей. У большинства из них нет подходящих креативов или нет ставок от вашего bidder.

Три представления по измерениям в Cat-Scan (гео, издатель, размер) превращают сырые числа воронки в готовые к действию списки исключений.

## Три представления

### Потери по географии

Показывает QPS, ставки, выигрыши, расходы и коэффициент потерь по стране и городу.

Типичные находки:
- Большой QPS из стран, для которых у вас нет креативов или бюджета.
- Города, получающие непропорциональный объём, но почти без выигрышей.
- Целые регионы, которые bidder полностью игнорирует.

Действие: Добавьте наихудшие гео в список исключений соответствующей конфигурации pretargeting.

### Потери по издателям

Ранжирует домены и пакеты приложений по полученному объёму против размещённых ставок и расходов.

Типичные находки:
- Высококачественные по QPS издатели, у которых bidder делает ставки менее чем на <5% запросов.
- Приложения, доставляющие объём, но с нулевыми выигрышами (часто из-за пола или несоответствия креатива).
- Длинный хвост низкокачественного инвентаря, по-прежнему потребляющего ваш выделенный QPS.

Действие: Используйте редактор издателей для конфига, чтобы заблокировать наихудших. Это значительно проще, чем работа с CSV-шаблонами Google.

**Атомарный факт:** Редактор блокировки/разрешения издателей Cat-Scan работает на конфиг и поддерживает поиск + массовые изменения с предпросмотром.

### Потери по размерам

Google с удовольствием отправит вам 300+ различных размеров объявлений, даже если у вас есть креативы только для нескольких.

Типичная находка: 80%+ QPS в размерах, для которых у вас вообще нет креатива.

Действие: Явно перечислите только те размеры, которые вы реально поддерживаете, в конфигурации pretargeting. Это одно из наиболее высокоэффективных одиночных изменений, которое может сделать большинство новых мест.

## Как строятся данные

Все три представления вычисляются из объединённого набора данных пяти отчётов после импорта. Для самого анализа дополнительные обращения к Google API не требуются (синхронизация pretargeting — отдельный процесс).

Те же данные питают воронку на главной странице и предложения оптимизатора.

## Почему этот анализ редко встречается

Большинство агентств никогда не видят эти разбивки, потому что никогда не объединяют пять CSV и никогда не строят агрегаты по измерениям. Они смотрят на высокоуровневые отчёты эффективности, которые присылает Google, и предполагают, что «bidder разберётся».

Bidder может разобраться только с тем, что до него фактически доходит. Всё, что до него доходит, но отклоняется, уже стоило вам выделения QPS и инфраструктуры.
